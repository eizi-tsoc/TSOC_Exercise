# TSOC Exercise Web — System Specification

## 1. Source of truth
- 運動名・目的・説明・画像の向き/順序/配置: `TSOC_Exercise_2v4.xlsm`（選択用Excel）を基準とする。
- 最終印刷フォーム: `TSOC_Exercise_2v4_output.xlsm` の Sheet4 を基準とする。
- 印刷用Excelにある高解像度画像は、将来の印刷品質向上用素材として扱う。
- Excel上で写真へ重ねた赤矢印等は将来「完成画像」に固定して差し替える。Web側でExcel図形を無理に再現しない。

## 2. Category model
11個のシート名をすべて「カテゴリー（運動へ到達する入口）」として扱う。プリセットという概念・表記は使用しない。

- ストレッチ（上肢）
- ストレッチ（下肢）
- 肩インナーex
- ストレッチポール
- 上肢トレーニング
- 下肢トレーニング
- 体幹トレーニング
- 野球パターン
- 腰痛体操
- 肩体操
- 膝体操

同一運動は1つの運動データとして管理し、複数カテゴリーへ所属できる。カテゴリーのどこから選択しても同じ運動IDを選択する。

## 3. Selection / UI
- 最大8種目。
- デスクトップでは左「カテゴリー」と右「選択中の運動」を常時表示し、中央の運動一覧のみスクロールする。
- 選択操作自体は既存Web版と同様。選択済み一覧ではサムネイルを表示する。
- 選択済み一覧の「▲ / ▼」ボタンで印刷順を上下に変更できる。ドラッグ操作は使用しない。
- 回数/時間: 1～10 / 20 / 30 / 40 / 60 を選択可能。
- 単位: 回 / 秒。
- セット数: 1～10 を選択可能。
- 上記選択肢は `data/app-config.js` で変更可能とし、将来管理画面から編集できる構造へ発展させる。
- 患者名を入力。印刷ヘッダーでは入力された氏名の後ろに「様」のみを表示する。
- 同一運動の重複選択は不可。

## 4. Print / PDF
現行出力Excelの Sheet4 を基準にする。
- A4横。
- 1ページ4枠（2列×2段）を固定。
- 最大8種目 = 最大2ページ。
- 患者名、種目名、目的、回数/秒・セット、画像、QR、説明を出力。
- 4枠に満たない場合、空き枠にはTSOCロゴを表示して空間を埋める。
- 5～8種目の場合は2ページ目を生成し、2ページ目の不足枠にもTSOCロゴを表示する。
- ヘッダーには「TSOC_エクササイズパンフレット」、氏名欄、Tokyo Sports & Orthopaedic Clinicロゴを表示。
- ブラウザ印刷と「PDFに保存」を使用可能。

## 5. QR / Image policy
- 全運動のQRは `TSOC_Exercise_2v4_output.xlsm` Sheet7 を基準に対応付ける。
- Web選択画面: `images` の軽量画像を使用。
- 印刷/PDF: `print_images` が設定されている場合は高解像度画像を優先使用する。
- `print_images` が未設定の場合は `images` を自動使用し、既存運動を欠落させない。
- 印刷用画像専用の回転情報は `print_image_transforms` で保持可能。高解像度画像が未設定の場合は `image_transforms` を使用する。
- 画像の回転情報は選択用ExcelのDrawingMLから保持する。

## 6. Future management
管理者のみが運動マスターを追加・修正・更新できる管理機能を構築する。対象候補: 運動名、目的、説明、画像、カテゴリー所属、表示順、QR/動画、高解像度印刷画像、回数/時間候補、セット数候補。

## 7. Future patient record
患者ID + 発行日をキーとして、PDF保存とカルテアップロード用記録を想定する。選択運動・回数等をカルテへ貼り付けるためのサマリーコピー機能も追加候補。患者情報はPublic GitHubリポジトリへ保存しない。
